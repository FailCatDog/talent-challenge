# [100]揭榜功能完善阶段实施文档.md

## 背景与目标

为支撑揭榜挂帅业务闭环，本阶段围绕“资料补全、项目信息增强、揭榜查询完善”三个方向实施开发，目标是：

1. 用户侧具备完整资料查询能力（含学生/企业扩展信息）。
2. 项目列表展示对业务更有价值（带发布方、热度、预期结束时间）。
3. 揭榜查询可同时满足公开展示与学生自查场景。

## 一、范围与交付

### 1.1 用户资料能力
- 扩展并打通用户资料字段（学生/企业）。
- 支持资料更新与详情查询。

### 1.2 项目列表能力
- 热门、最新项目接口返回新增字段：`publisherName`、`viewCount`、`expectedEndDate`。

### 1.3 揭榜能力
- 新增公开揭榜名单查询。
- 新增学生“我的揭榜”查询。
- 维持揭榜撤回能力并校验权限。

## 二、实施方案

### 2.1 分层改造原则
- Trigger 层负责鉴权、参数承接与返回组装。
- Domain 层负责业务约束与编排。
- Infrastructure 层负责 SQL 查询与 DTO 映射。
- API 层承载对外 DTO 契约。

### 2.2 关键改动点
- Bid 相关：新增公开查询与学生查询方法，扩展 Mapper SQL。
- Project 相关：热门/最新查询结果扩展发布方与浏览等字段。
- User 相关：资料字段与查询链路对齐。
- Maven 依赖：修复 DTO 所在模块在下游不可见问题。

## 四、验证记录

### 4.1 构建验证
- 处理后项目可正常构建（用户本地 IDE 构建成功）。

### 4.2 接口验证清单
- `GET /api/v1/bid/public/project/{projectId}`：可返回公开揭榜信息列表。
- `GET /api/v1/bid/student/my-bids`：学生可查看所在团队揭榜记录。
- `GET /api/v1/project/popular`：返回包含 `publisherName/viewCount/expectedEndDate`。
- `GET /api/v1/project/latest`：返回包含 `publisherName/viewCount/expectedEndDate`。

### 4.3 安全与权限验证
- 学生接口限制学生身份。
- 企业接口限制企业身份。
- 公开接口不暴露竞榜内容与附件等敏感字段。
