# 功能模块文档

## 一、背景与目标

当前阶段聚焦“用户资料扩展与揭榜功能完善”，目标是补齐学生/企业资料能力、完善项目列表展示字段，并补足揭榜公开查询与学生自查能力，保证核心业务流程可用且可文档化。

## 二、本次已完成模块

### 1. 用户资料扩展模块
- 完成学生与企业扩展字段的数据链路（Domain / Infrastructure / API）。
- 已支持用户资料更新与按用户ID查询资料详情。

### 2. 项目列表信息完善模块
- 热门项目接口与最新项目接口已支持返回：
  - `publisherName`（发布企业名称）
  - `viewCount`（浏览量）
  - `expectedEndDate`（预期结束时间）

### 3. 揭榜管理完善模块
- 已新增公开揭榜名单查询接口：
  - `GET /api/v1/bid/public/project/{projectId}`
- 已新增学生“我的揭榜”查询接口：
  - `GET /api/v1/bid/student/my-bids`
- 已保留并验证揭榜撤回能力：
  - `POST /api/v1/bid/cancel/{bidId}`

## 三、权限与数据可见性规则

- 学生接口：仅学生角色可访问（如 `student/my-bids`、`cancel`）。
- 企业接口：仅企业角色可访问（如 shortlist / confirm / reject / project bids）。
- 公开接口：`public/project/{projectId}` 对外开放，仅返回非敏感揭榜信息（不返回 content/attachmentUrl）。

## 四、本阶段联调与验证结论

1. 代码层面已完成新增接口全链路（Controller → Service → Repository → Mapper）。
2. 编译问题已修复：
   - 跨模块 DTO 依赖缺失问题已处理。
   - `int` 类型比较方式错误已处理。
3. API 文档已同步更新：
   - 新增揭榜公开查询与学生我的揭榜接口说明。
   - 热门/最新项目返回示例已补充新增字段。

## 六、team_member 关联表补充（2026-03-09）

### 背景
原"学生我的揭榜"接口依赖不存在的 `team_member` 表导致 500 错误，同时团队详情/我的团队接口缺少成员信息。

### 改动内容
- 新增 `team_member` 表（team_id、user_id、role、join_time），支持队长/普通成员区分。
- 创建团队时同步写入队长 `team_member` 记录。
- `GET /api/v1/team/detail/{teamId}` 和 `GET /api/v1/team/my` 返回值新增 `members` 字段（含昵称、头像、角色）。
- `GET /api/v1/bid/student/my-bids` 改为 JOIN `team_member`，普通队员也能查到团队揭榜记录。

### 当前状态
- team_member 表已建，代码已完成，文档已同步。
- 存量团队需手动补一条队长记录：
  ```sql
  INSERT INTO team_member (team_id, user_id, role, join_time)
  VALUES ('2020476698205753344', '2018608120762339328', 'leader', NOW());
  ```
