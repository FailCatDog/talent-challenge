## 文件存储配置说明（可自行修改）

项目的文件上传路径与对外访问 URL 通过 `application.yml` 统一配置，无需在启动时额外传参。

```yaml
file:
  upload:
    # 本地磁盘根目录（绝对路径），默认使用项目根目录下的 files
    base-dir: ${user.dir}/files
    # 对外访问的 URL 前缀（相对路径或 CDN 完整前缀）
    url-prefix: /static
    path:
      milestones: milestones
      qualifications: qualifications
      bids: bids
    max-size: 10485760  # 10MB（字节）
    allowed-types: pdf,doc,docx,jpg,jpeg,png,zip,rar
```

**说明**：
- `base-dir` 为实际存放文件的绝对路径，部署到不同机器时只需修改此项。
- `url-prefix` 为前端访问文件时使用的 URL 前缀，若后期迁移到 CDN，只需改为 `https://cdn.example.com/static`。
- `path.*` 为业务子目录的相对路径，会在 `base-dir` 下自动创建。

系统在 `WebMvcConfig` 中把 `${base-dir}` 映射到 `${url-prefix}`，文件上传后返回的 URL 已经是相对路径（例如 `/static/qualifications/123/file.pdf`），前端可直接使用。

## 六、企业资质审核模块

**完成时间**：2026-03-11

**做了什么**：
- `company_profile` 表新增 `certification_status`、`reject_reason`、`certified_at` 三个字段，默认状态为 `uncertified`。
- 新增 `CertificationStatusEnum` 枚举（uncertified / pending_review / certified / rejected）。
- 扩展 `StorageService`，支持企业资质文件上传，存储路径 `data/qualifications/{userId}/`，静态访问路径 `/static/qualifications/**`。
- 完整实现企业资质审核链路：企业上传文件 → 提交审核（状态变 pending_review）→ 管理员查看列表 → 通过（certified）/ 拒绝（rejected，含原因）。
- `UserProfileResponseDTO` 新增 `certificationStatus`、`rejectReason`、`certifiedAt` 字段，查看资料接口同步返回认证状态。

**新增接口**：
- `POST /api/v1/user_management/company/upload_qualification` — 企业上传资质文件
- `POST /api/v1/user_management/company/submit_qualification` — 企业提交资质审核
- `GET /api/v1/user_management/admin/company/pending_review` — 管理员查询企业列表（按认证状态分页）
- `POST /api/v1/user_management/admin/company/approve/{userId}` — 管理员通过认证
- `POST /api/v1/user_management/admin/company/reject/{userId}` — 管理员拒绝认证

**相关接口**：见 `[002]API文档.md` → 用户管理模块 → 接口 6-10
