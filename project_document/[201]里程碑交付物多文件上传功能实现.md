# 里程碑交付物多文件上传功能实现

## 背景与目标

### 背景
学生提交里程碑交付物时，需要支持多文件上传并保存完整的文件信息（文件名、URL、大小、上传时间）。原有实现中，`deliverableFiles` 字段无法正确保存文件大小信息。

### 目标
- 完善里程碑交付物提交接口，支持传递完整的文件信息
- 确保 `deliverableFiles` JSON数组包含完整的文件元数据
- 支持重复提交，采用追加方式保存提交历史

---

## 实现方案

### 方案选择
采用**修改接口参数**方案：
- 修改 `/api/v1/milestone/deliverable` 接口，接收完整的文件信息对象
- 前端先调用文件上传接口获取文件信息，再调用提交接口

### 核心修改

#### 1. DTO 修改
`MilestoneDeliverableRequestDTO` 新增字段：
```java
private String fileName;      // 文件名
private Long fileSize;        // 文件大小（字节）
```

#### 2. Service 方法签名修改
```java
boolean submitMilestoneDeliverable(
    String milestoneId,
    String fileName,
    String deliverableUrl,
    Long fileSize
);
```

#### 3. 文件信息存储格式
`deliverableFiles` JSON数组格式：
```json
[
  {
    "fileName": "方案文档.pdf",
    "fileUrl": "/static/milestones/xxx/xxx.pdf",
    "fileSize": 102400,
    "uploadTime": "2026-03-13T12:00:00"
  }
]
```

---

## 接口变更说明

### 接口：提交里程碑交付物
**路径**：`POST /api/v1/milestone/deliverable`

**请求参数变更**：
```json
{
  "milestoneId": "里程碑ID",
  "fileName": "文件名.pdf",
  "deliverableUrl": "/static/milestones/xxx/xxx.pdf",
  "fileSize": 102400,
  "remark": "备注"
}
```

**返回示例**：
```json
{
  "code": "0000",
  "info": "成功",
  "data": true
}
```

---

## 使用流程

### 完整流程
1. **上传文件**：调用 `/api/v1/milestone/deliverable/files/upload`
2. **提交里程碑**：调用 `/api/v1/milestone/deliverable`
3. **重复提交**：支持多次提交，每次追加新的文件信息

### 前端示例
```javascript
const uploadResponse = await uploadFile(milestoneId, file);
await submitMilestone({
  milestoneId: milestoneId,
  fileName: file.name,
  deliverableUrl: uploadResponse.data,
  fileSize: file.size
});
```

---

## 特性说明

### 1. 支持重复提交
- 允许 `in_progress` 和 `delivered` 状态的里程碑提交
- 每次提交追加到 `deliverableFiles` 数组

### 2. 数据完整性
- `deliverableUrl`：最新提交的文件URL
- `deliverableFiles`：所有提交的文件历史
